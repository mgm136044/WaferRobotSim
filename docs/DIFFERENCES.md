# 실제 로봇과 다를 수 있는 부분

시뮬레이터는 **코드 쪽(타이밍·통신·제어 흐름)은 실물과 같게**, **물리 쪽은 단순화 + 보정 가능한 값**으로 만들었습니다.
아래 항목은 결과를 해석할 때 꼭 고려하세요. 설정 탭의 각 값 옆에 "실측/가정" 출처가 적혀 있습니다.

## 1. 주행(바퀴) 모델
| 항목 | 시뮬레이터 | 영향 / 보정 방법 |
|---|---|---|
| PRIZM 속도 PID | 펌웨어 내부가 비공개라 **실측 기반 등가 모델** 사용: 명령 지연 110 ms + 1차 지연 60 ms + 추종 비율 0.77 (실제/명령) | 실물 로그 `명령 100 → 실제 75~77.5 deg/s` 한 가지 조건으로 맞춤(실측 비교 RMS 약 2 deg/s, docs/VERIFICATION.md). **고속(720 deg/s)·감속 구간은 외삽**이므로 실물 BASE_TRACE로 다시 맞추세요. `setMotorSpeedPID()`는 무시(경고만) |
| 최고 속도 | TorqueNADO 60:1 (무부하 100 rpm = 600 deg/s, 12 V)를 전압·전류 모델로 계산 | 720 deg/s 명령은 실물에서도 포화될 가능성이 큼. 배터리 전압(기본 12.6 V) 바꾸면 달라짐 |
| 바퀴 / 이동량 | **실측** 바퀴 지름 103 mm → 바퀴 1회전 323.6 mm. 모터↔바퀴 기어 1:2(교육자료: 40T→80T)라 모터(엔코더) 1회전 = 161.8 mm | 기어가 직결이면 설정 `모터 회전 / 바퀴 회전`을 1로. 타이어 미끄럼(크리프)으로 등속 주행 시 실제 이동은 약 0.2% 짧음 |
| 브레이크(파워 125) / 코스트(파워 0) | 모터 단락 제동 / 전원 개방 + 기어 마찰 0.17 N·m, 바퀴 미끄럼 한계 μ=0.7, 질량 6 kg, 구름저항 2 N | 정지 거리·코스트 거리는 이 가정값에 좌우됨 → 실물 정지 위치와 비교해 μ·마찰 조정 |
| 차체 운동 | **평면 강체(앞뒤·좌우·회전)**를 무게중심(구동축 하중 비율 0.55 → 모터축 뒤 100.8 mm)에서 적분. 로봇 가운데를 지나는 **레일 1개**를 앞·뒤 축의 가이드 롤러가 양옆에서 물고 있음(한쪽 틈새 1 mm, 넘으면 200 N/mm 접촉력). 비구동 바퀴는 옴니휠로 가정(옆방향 힘이 일반 바퀴의 5%, 상한도 5%) | 레일 단면·롤러 위치·틈새·강성, 하중 비율은 **가정값**. 좌우 바퀴 차이는 기본 0(설정 `오른쪽 바퀴 유효 지름 배율`로 시험). 롤러 걸림·진동·바닥 요철·레일 이음매는 없음 |
| 배터리 | 전압 일정 | 실물은 주행 중 전압 강하 → 속도 감소 |

## 2. 라인 센서 / 경기장
- 센서 판정은 **이상적인 띠**(선 폭 ± 여유값) + 고정 응답 지연 0.3 ms. 실제 IR 센서의 높이·반사율·주변광·히스테리시스·경계 노이즈는 없음.
- **실측 반영** (2026-11-19 팀 실측):
  - 경기장: 한 칸(흰색만) 470 mm, 맨 끝 칸(0번 앞·4번 뒤) 150 mm, 검은 선 10 mm
  - 모터축 = 앞바퀴, 바퀴 지름 103 mm
  - 로봇을 시작 위치 끝까지 붙였을 때 경기장 끝 → 모터축 중심 270 mm
  - 모터축 ↔ 뒷바퀴축 중심 224 mm
  - 4번 센서 = 모터축 중심 + 65 mm, 5번 센서 = 뒷바퀴축 중심 + 85 mm (둘 다 진행 방향 앞쪽으로 해석)
  - 결과: 출발 시 4번 센서는 335 mm, 5번 센서는 131 mm(0번 선보다 19 mm 뒤), 두 센서 간격 204 mm
- **가정값**:
  - 차체 길이 480 mm·폭 400 mm, 좌우 바퀴 간격 320 mm
  - 모터↔바퀴 기어 1:2(교육자료)
  - 뒷바퀴 지름 90 mm(표시용, 물리 영향 없음. 뒷바퀴축이 시작 끝에서 46 mm라 92 mm 이하여야 함)
  - 레일 틈새·강성
- **실물 로그와 맞지 않는 점 (팀 확인 필요)**: 11/12 실물 로그의 0번 정렬은 1.55 s 동안 엔코더 약 97°(기어 1:2 기준 약 44 mm)를 갔습니다. 실측 치수로는 로봇을 시작 끝에 끝까지 붙였을 때 5번 센서에서 0번 선까지 19 mm밖에 남지 않아, 시뮬은 19 mm가 최대입니다(붙이지 않았다면 더 짧아짐).
  - 로그 당시 로봇이 시작 위치(0번 선 뒤)에 있었다면 첫 칸 150 mm, 5번 센서 위치(뒷바퀴축 +85 mm), 축간 224 mm, 기어비 중 하나 이상이 실물과 다르다는 뜻입니다.
  - 시작 위치가 아닌 곳(예: 0번 선을 지난 곳)에서 찍은 로그라면 비교 대상이 아닙니다.
  - 확인 방법: 로봇을 시작 끝에 붙이고 BASE_TRACE 로그를 한 번 더 받아 `실측 비교` 탭이나 `tools/verify.mjs --real-log`로 비교하세요(검증표의 "⚠️ 확인 필요" 항목).
- 차체 길이 480 mm면 앞끝이 모터축 앞 210 mm라서 0→4 정지(4번 센서 통과 + 300 ms) 때 끝 벽에 41 mm/s로 닿습니다. 벽이 없을 때 모터축은 2028.1 mm에서 멈추므로, 전체 길이 **471 mm 이하**(앞끝이 모터축 앞 201 mm 이내)면 닿지 않습니다(471 mm: 여유 0.9 mm, 472 mm: 접촉).
- 센서는 레일 중심에서 왼쪽 50 mm(가정)에 있다고 계산합니다. 차체가 돌아갈 때만 감지 위치에 영향이 있고(0.5°에서 0.4 mm), 화면 표시와 같습니다.
- 경기장 기본값은 실측(라인과 라인 사이 470 mm = 선 중심 간격 480 mm, 선 폭 10 mm, 양 끝 150 mm)입니다. 이 값으로 계산한 전장은 **2,230 mm**로,
  규정 V1.3 도면의 1,860 mm(선 간격 370 mm)와 다릅니다. 실측 기준을 한 번 더 확인하세요. 설정에서 "규정 V1.3 도면" 프리셋으로 바꿀 수 있습니다.
- 경기장 양 끝은 단단한 벽으로 처리(차체 네 모서리 기준, 충돌 시 이벤트 기록). 옆 방향에는 벽이 없고, 차체가 작업 영역 폭 900 mm 밖으로 나가거나 레일을 끈 상태에서 가이드가 레일선에서 30 mm 넘게 벗어나면 **경고만** 남깁니다. 트레이와의 충돌은 없음.
- 시작 위치는 `로봇 뒤끝 → 모터축 270 mm` 하나로 정합니다(끝까지 붙인 상태). 다른 곳에서 시작하려면 `시작 시 로봇 뒤끝 ↔ 경기장 끝 간격`을 넣으세요.
- 계산할 수 없는 설정(질량 0, 바퀴 지름 0 등)은 실행할 때 기본값/허용 범위로 바꾸고, 뒷바퀴가 경기장 밖에 놓이거나 모든 센서가 이미 0번 선을 지난 배치는 컴파일 로그에 경고로 알려 줍니다.
- 3D와 물리는 모두 1 단위 = 1 mm입니다(경기장·로봇 동일 축척).

## 3. 팔 / Z / 손목 (주행 타이밍을 위해 포함, 단순화)
- AServo 2축은 CiA-402 SDO 프로토콜·상태 비트(PP 모드 setpoint ack, target reached, 호밍)를 흉내 내고, 궤적은 **이상적인 S-커브**(설정된 속도·가감속·저크 반영)로 정확히 목표에 정착합니다. 실제 위치 루프의 추종 오차·오버슈트·전류 제한은 없음.
- 팔·포크·웨이퍼·트레이의 **충돌과 웨이퍼 물리는 없습니다** → 웨이퍼 점수(6~8번 항목)는 계산하지 않습니다.
- 3D 팔 자세는 각도 부호·0점·팔 위치를 가정한 **표시용 근사**입니다(설정 → 시각화(팔)).
- 손목 서보: 100%에서 200 명령단위/s로 선형 이동(코드의 `WRIST_COMMAND_DPS_AT_100` 가정과 같은 값). 실측 아님.
- Z 스텝모터: 200 펄스/mm, 탈조 없음(기계 한계에서만 경고). 원점 스위치는 Z=0에서 동작.

## 4. 통신 / CPU 시간
- UART1(38400 bps) 바이트 시간은 정확히 반영. Serial-CAN 변환 지연 0.8 ms·드라이브 응답 1.0 ms는 실측 `ARM_START_COMMAND_GAP_MS`(평균 9.9 ms)에 맞춘 보정값 → SDO 1회 시뮬 9.92 ms. **통신 오류·패킷 손실·재시도 상황은 재현하지 않음.**
- I2C(400 kHz) 전송 시간 반영. 응답 없는 주소는 NACK + 경고(예: ToF 센서 미구현).
- CPU 연산 시간은 무시하고 API 호출마다 고정 비용만 씀(millis 1 µs, digitalRead 1 µs 등). 계산이 무거운 코드가 루프를 늦추는 효과는 반영 안 됨.
- 인터럽트(gptimer ISR, attachInterrupt)는 API 호출 사이에서만 실행(진짜 선점 아님). `portENTER_CRITICAL` 구간은 존중.
- USB 시리얼 출력은 막힘 없이 즉시 처리(USB 미연결 시 출력 대기 현상 미재현).

## 5. 지원하지 않거나 흉내만 내는 API
| API | 동작 |
|---|---|
| `xTaskCreate` 등 FreeRTOS 태스크 | 생성 실패 반환 + 경고 (멀티태스크 없음) |
| `getSonicSensor` / 초음파 | 0 반환 + 경고 |
| `EXPANSION` 컨트롤러 | 무시 + 경고 |
| ToF·컬러 등 I2C 센서 라이브러리 | 컴파일은 되지만 장치 응답 없음(NACK) |
| 아날로그 입력 | 디지털 레벨 기반 0/4095 |
| 사운드, NeoPixel 패턴 | 걸리는 시간만 반영 |
| Wi-Fi/BLE, SPI, EEPROM/Preferences, 파일시스템 | 없음 → 링크 오류로 표시 |
| `PrizmEnd()` | 모터 정지 후 시뮬레이션 종료 (실물은 워치독 리셋 후 다시 START 대기) |

## 6. 컴파일 환경 차이
- ESP32와 같은 32비트(ILP32), `char`는 unsigned로 맞춤, `-std=gnu++2b`, 예외·RTTI 끔.
- 실제 ESP32 RAM 한도(약 512 KB)·스택 크기·워치독 리셋은 적용하지 않음. 배열 범위 초과 같은 메모리 오류는 실물과 다르게 나타날 수 있음(시뮬레이터에서 잡히면 "런타임 오류"로 표시).
- 부동소수점 결과가 미세하게 다를 수 있음.
